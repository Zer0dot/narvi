# Narvi — Hyprland Color-Management Suite

**One-liner:** A real-time digital-vibrance and color-grading tool for Hyprland —
vibrance, temperature, brightness/contrast, gamma, and per-channel RGB, driven by a
live GUI, tray, CLI, and daemon. The Wayland answer to nvidia-settings' Digital
Vibrance, but a whole color pipeline.

Narvi is a moon of Saturn; the project is part of a Saturn-themed family.

---

## Goals / Non-goals

**Goals**
- One cohesive color pipeline, hot-applied with zero flicker.
- Profiles, per-app auto-switching, and day/night scheduling.
- Four interaction surfaces (GUI, tray, CLI, daemon) over a single source of truth.

**Non-goals (v1)**
- Non-Hyprland compositors.
- Per-monitor color. Hyprland `decoration:screen_shader` is global; per-output color
  needs DRM CTM, which the NVIDIA proprietary driver does not honor.
- ICC / calibration-grade color management.

---

## Architecture

- **`narvid` (daemon):** owns state, generates the combined fragment shader,
  hot-reloads it via `hyprctl keyword decoration:screen_shader`, runs scheduling, and
  watches Hyprland's event socket (`socket2`, `activewindow`) for per-app auto-switch.
- **Clients (GUI, tray, CLI):** thin front-ends that talk to `narvid` over a **Unix
  domain socket** using newline-delimited JSON. Single source of truth, no races.
  GUI and tray auto-start `narvid` after a short unreachable grace (via the
  `narvi.service` user unit when present, else a detached exec; gives up after
  repeated failures; `NARVI_AUTOSPAWN=0` opts out); the CLI never does. A flock
  next to the socket enforces a single daemon instance.
- **Hotkeys (Wayland-correct):** Hyprland keybinds invoke the `narvi` CLI
  (`narvi nudge vibrance +0.05`, `narvi profile next`, `narvi toggle`), which messages
  the daemon. The home-manager module ships sensible default binds.

```
 Hyprland keybinds ─┐
 tray (ksni) ───────┼──▶ narvi CLI / socket ──▶ narvid ──▶ ~/.config/hypr/shaders/narvi.frag
 GUI (egui) ────────┘                              │              │
                                                   │              └─▶ hyprctl keyword decoration:screen_shader
                                                   ├─▶ Hyprland socket2 (activewindow → auto-switch)
                                                   └─▶ scheduler (sunrise/sunset transitions)
```

## Color pipeline (single generated shader)

GLSL ES, generated by the daemon and hot-reloaded on every change.

**Shader interface (Hyprland 0.55.x / aquamarine — confirmed):**
- `#version 300 es`
- `precision highp float;`
- `in vec2 v_texcoord;`
- `uniform sampler2D tex;`
- `out vec4 fragColor;`
- sample with `texture(tex, v_texcoord)`

**Order of operations:**

1. brightness
2. contrast
3. temperature (white balance)
4. gamma
5. per-channel RGB gain
6. protective vibrance (last)

Vibrance uses the luma-weighted curve that boosts muted colors more than
already-saturated ones and protects skin tones (the nvidia-settings feel). All
parameters compose into one cheap fullscreen pass.

**Reload mechanics:** Hyprland compiles the shader when the option is *set*, not
continuously. The daemon regenerates `narvi.frag` then re-issues
`hyprctl keyword decoration:screen_shader <path>`. Disable with the `[[EMPTY]]` token.

## Features

- **Controls:** vibrance/saturation, temperature (K), brightness, contrast, gamma,
  R/G/B gain.
- **Profiles:** named, saved in TOML. Built-in presets: **Default, Gaming, Movie,
  Photo, Night.**
- **Per-app auto-switch:** match on **window class / app-id** (e.g. `steam_app_*`,
  `mpv`); the daemon swaps profiles on focus change.
- **Scheduling:** **sun-based** — sunrise/sunset from geoclue or manual lat/long, with
  smooth transitions between a day profile and a night profile.
- **Live preview:** a bundled **sample image** processed through the real pipeline
  (v1); user-replaceable image path. Desktop freeze-frame is a stretch goal.

---

## Interfaces

- **GUI (egui):** dashboard-with-live-preview layout; **minimal line sliders + editable
  numeric fields**; profile picker; Reset / Save.
- **Tray (StatusNotifierItem / `ksni`):** **click toggles the panel**; menu for presets
  + quit.
- **CLI:** scriptable, for keybinds and automation.
  - `narvi set vibrance 1.3`
  - `narvi nudge vibrance +0.05`
  - `narvi profile gaming` / `narvi profile next`
  - `narvi toggle` / `narvi off`
  - `narvi restore`
- **Daemon (`narvid`):** persistence, restore-on-login, scheduling, auto-switch.

## Config (TOML)

`~/.config/narvi/config.toml`. The generated shader lands at
`~/.config/hypr/shaders/narvi.frag` (mutable, outside the Nix store).

```toml
[general]
active_profile = "default"
restore_on_start = true

[hyprland]
shader_path = "~/.config/hypr/shaders/narvi.frag"   # generated

[scheduling]
enabled = true
mode = "sun"            # "sun" | "fixed" | "off"
latitude = 40.71        # or rely on geoclue
longitude = -74.01
day_profile = "default"
night_profile = "night"
transition_minutes = 30

[ui]
theme = "saturn"
accent = "#E0A23C"
preview = "sample"      # "sample" | "gradient" | "desktop"
preview_image = ""      # optional override

[[profiles]]
name = "default"
vibrance = 1.25
saturation = 1.0
temperature = 6500      # K
brightness = 1.0
contrast = 1.0
gamma = 1.0
rgb = [1.0, 1.0, 1.0]

[[profiles]]
name = "gaming"
vibrance = 1.5
saturation = 1.1
temperature = 6500
brightness = 1.0
contrast = 1.05
gamma = 1.0
rgb = [1.0, 1.0, 1.0]
match = ["steam_app_*", "gamescope"]   # auto-switch on these classes

[[profiles]]
name = "night"
vibrance = 1.1
temperature = 3800
brightness = 0.95
contrast = 1.0
gamma = 1.0
rgb = [1.0, 1.0, 1.0]
```

## Notes / constraints

- `decoration:screen_shader` is **global** across all monitors. Acceptable for v1;
  per-monitor is out of scope (CTM unsupported on the NVIDIA proprietary driver).
- Temperature here overlaps with `hyprsunset` / `gammastep`. Narvi owns the whole
  shader, so those should not run simultaneously; document this.
- Screen shaders can briefly artifact on window-close/manipulation (known Hyprland
  behavior, upstream issue #8561) — independent of Narvi.
